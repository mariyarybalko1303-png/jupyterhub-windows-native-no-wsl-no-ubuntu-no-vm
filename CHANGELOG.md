Оновлення проєкту (Changelog & Architectural Updates)📌 Загальний підсумок останніх змінУ межах оптимізації дослідницького стенда багатокористувацької платформи JupyterHub на базі Windows без використання віртуалізації були проведені такі системні та архітектурні модифікації:Інтегровано підтримку логічного програмування (SWI-Prolog Kernel) на додаток до Python 3 та Kotlin.   Розгорнуто та налаштовано хмарну синхронізацію робочого простору через офіційний клієнт Google Drive for Desktop.   Вирішено проблему кодувань шляхів у Windows API, забезпечивши повну підтримку UTF-8 для кириличних назв директорій.   Усунено конфлікти токенів безпеки (XSRF) та сесійних файлів cookie під час оновлення робочої директорії сервера.🛠 Детальний журнал внесених змін1. Інтеграція ядра SWI-Prolog (Логічне програмування)Встановлення середовища: нативно розгорнуто компілятор SWI-Prolog v10.0.2 за допомогою інструменту Windows Package Manager:PowerShellwinget install SWI-Prolog.SWI-Prolog
Додавання бінарних файлів у середовище: зареєстровано шлях до виконуваного файлу swipl.exe у системній змінній PATH:PowerShell[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Program Files\swipl\bin", [EnvironmentVariableTarget]::Machine)
Інтеграція в інтерфейс Jupyter: встановлено пакет prolog-kernel та зв'язку pyswip, після чого виконано реєстрацію специфікації ядра:PowerShellpip install prolog-kernel pyswip
python -m prolog_kernel.install
Результат: тепер у меню Launcher поряд із python3 та kotlin доступна плиткова кнопка запуску блокнота Prolog.   2. Підключення хмарного сховища Google DriveМонтування віртуального накопичувача: встановлено клієнт Google Drive for Desktop (winget install Google.GoogleDrive), який монтує обліковий запис у вигляді локального тома G:\.Створення структури теки: згенеровано виділену директорію для синхронізації робочих проєктів:PowerShellNew-Item -ItemType Directory -Path "G:\Мой диск\JupyterHub_Workspaces" -Force
Перенаправлення кореня Spawner: замість збереження у локальному тимчасовому каталозі базовий шлях для користувацьких серверів переведено на Google Диск:Pythonc.Spawner.notebook_dir = r'G:\Мой диск\JupyterHub_Workspaces'
Результат: усі створені користувачами файли та блокноти автоматично зберігаються на фізичному диску та у фоновому режимі відправляються в хмару Google Drive.3. Виправлення кодування конфігурації (UTF-8 Fix)Проблема: при внесенні кириличного шляху G:\Мой диск\... засобами консолі PowerShell файл було збережено з однобайтним кодуванням Windows-1251 (ANSI). Це викликало критичну помилку компіляції під час запуску JupyterHub:PlaintextSyntaxError: (unicode error) 'utf-8' codec can't decode byte 0xcc in position 3: invalid continuation byte
Рішення: реалізовано скрипт очищення та перезапису конфігураційного файлу із явним заданням кодування [System.Text.Encoding]::UTF8:PowerShell$lines = Get-Content "C:\jupyterhub\jupyterhub_config.py" | Where-Object { $_ -notmatch 'notebook_dir' }
$lines += "c.Spawner.notebook_dir = r'G:\Мой диск\JupyterHub_Workspaces'"
[System.IO.File]::WriteAllLines("C:\jupyterhub\jupyterhub_config.py", [string[]]$lines, [System.Text.Encoding]::UTF8)
Результат: конфігурація стабільно читається парсером Python незалежно від локалізації та спеціальних символів у шляхах.   4. Оновлення сесій та усунення помилок XSRF 403 ForbiddenПроблема: після зміни кореневого шляху робочого простору та перезапуску служби клієнтські сесії браузера намагалися звертатися до старих ідентифікаторів сокетів та застарілих XSRF-токенів:Plaintext403 GET /user/testuser/api/kernels/... Not accepting incorrect xsrf token id in cookie
Рішення: скинуто застарілі файли cookie в браузері (через очищення сесії або запуск у режимі інкогніто), що змусило сервер створити нову пару ключів автентифікації без конфліктів.
